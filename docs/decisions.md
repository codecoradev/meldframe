| 40 | The Properties panel of W1 is the built panel of `docs/ui-design.md` section 3.1, and six items the first design pass promised stay out of it when it was approved (items 3, for the Remove button only, and 4 were built afterwards: see each item and the status). (1) **Grid layout**: out. `LayoutMode` is none, row or column; there is no column or row field in the model, no grid in the layout core or the export, and the fidelity contract (section 4) lists CSS grid as unsupported until a core implementation and oracle fixtures exist. It needs its own epic box after W1 and a model round like ADR-0013. Follow-up: #271 (grid layout plan). (2) **Border per side**: out. The model's `border` is one width, colour and position; the contract lists per-side border as unsupported, and the export writes the border as one `::after` ring. The ring itself could take four widths (`border-width: t r b l`); what cannot is the one-width `after()` function of the export, the canvas ring (one circular radius), the `Border` value, the check, the panel and the importer. A contract change comes first, then model, canvas, export and oracle. Follow-up: #270 (per-side border proposal), written as `docs/per-side-border.md` (proposal, awaiting the owner). (3) **Border visibility and remove**: no visibility switch (hiding while keeping the width needs a model field, as in item 6) and no Remove button in the first W1 pass. A width of 0 is no border (`Border.width`, "0 = no border"), the Border width field takes 0 and sends the same `borderWidth` command as an agent, and the position control hides at 0. A Remove button that sends that one command was built afterwards as the small later slice (#267, merged as #276). A shadow keeps its Remove button and has no visibility switch either. (4) **Scales other than 1x and 2x**: not in the first W1 pass, and cheaper than the issue assumed. The PNG is drawn by the canvas offscreen, as a capture is, not by the `export` crate (which writes HTML); the limit is `EXPORT_SCALES` in `packages/web-document/src/export.ts`, held by the page, and the `capture` tool and its relay already take any scale above 0 and up to 4. The E4.3 box was checked at 1x and 2x only, and the 4096 x 4096 px area limit refuses a large frame at the higher scales, so the first W1 pass kept 1x and 2x. Offering 0.5x to 4x was the later slice: it widened the constant, refuses a scale over the area limit before saving, was checked in a browser at each scale, and the E4.3 text was updated (#268, merged as #274). (5) **File name field**: out, not planned. The PNG is saved as the frame's name with the characters a file system refuses turned into `-`, cut to 80 characters, `@<scale>x` for a scale other than 1x and `.png`; the HTML as `<name>.html`; both are shown before saving, and renaming the frame renames the file. The Tailwind style sheet has the name the HTML links, so a free name would reach into the export, and the field would need a home for its state. No follow-up issue: not planned. (6) **Visibility**: out. A node has no `visible` field (the coverage table of `meldframe-render` has none) and neither has a border or a shadow, so it needs a model field with its meaning decided first: whether a hidden node keeps its place in a flow, how a capture, the export (`display` or `visibility`) and the layers panel treat it, undo, and the tool text. That is an ADR, then the contract rows, not a panel control. Follow-up: #269 (ADR on node visibility). Opacity 0 is the way to hide the paint today. The page has no fields either (no page background, opacity or visibility: the file holds nodes only), so the empty panel says so. Also recorded: the note named rows the panel does not have or has differently (Export is below Properties, Margin is its own section, padding shows all sides, sizes have no unit control, no border sides), and the Text section now has weight and alignment, Appearance has Clip content, and the toolbar has an Ellipse tool (#262, #263). | decided (owner approval, 24 Nov 2026; follow-up issues #267 to #271, none for item 5; items 3 and 4 were built afterwards, as #276 and #274) |
